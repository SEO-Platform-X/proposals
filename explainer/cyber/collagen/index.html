What happened to the website in early November

Spam pages were placed on the website for about a day. The site is clean, now runs on new hardened hosting, and there is no evidence any customer data was taken. Here is what happened, what it touched, and what has been done.

The short version

The bottom line

  • Attackers got in through a flaw in the YOOtheme Pro theme that let anyone drop a file onto a site without logging in. No passwords were stolen or guessed.
  • They used it to hijack 12 of our page addresses and show Indonesian gambling spam there, to borrow our site's standing on Google.
  • The spam was live for roughly one day and was removed on Nov 2. The site is verified clean today.
  • There is no evidence customer, lead or portal data was accessed. As a precaution, every login was reset and the site was moved to a new server.
  • Two decisions sit with leadership: a precautionary portal password reset, and cleaning up the Google Ads conversion that counts page views.
When and how

From public flaw to cleanup

On Oct 22, the company behind YOOtheme Pro, the page-builder theme the site runs on, announced a critical security flaw (CVE-2026-102785). Attackers began scanning for it almost immediately, and our site was reached before the fix was applied.

  1. Oct 22
    Theme flaw made public

    Anyone could upload a file to an affected site without logging in.

  2. Oct 26
    Automated break-in

    The site was hit at 11:24 UTC, before the theme patch reached it.

  3. Oct 28
    Tools staged

    The attacker used that foothold to stage files for later use.

  4. Nov 2
    Spam pages go live

    A rogue plugin hijacked 12 pages, and the attacker added themselves as a Search Console owner.

  5. Nov 2
    Caught and removed

    Every planted file was removed after roughly a day, the theme was moved to the patched release, and the attacker's Search Console access was revoked.

  6. Nov 6
    Verified clean, reindexing requested

    Google's live test returns the real pages. Reindexing of the affected pages is underway.

Every other site our team manages has also been checked for the same flaw.

How the trick works

A hidden plugin swapped 12 pages

It was not a redirect or a classic cloaking hack. A small rogue plugin intercepted twelve real page addresses, including /press/, /collagen-pin-treatment/ and /collagen-pin-about/, and served static gambling pages in their place. The rest of the site worked as normal.

Why this site was chosen

This is common, and it is automated

When a serious WordPress flaw is announced, spam networks start running bots that sweep the web for every site still running the vulnerable version. When a bot gets in, it plants spam and moves on. Sites with a strong Google reputation are the most valuable to them, because spam on a trusted site ranks fast.

In other words, the site was hit because it ran the affected theme and Google trusts it, not because anyone targeted Induction Therapies.

Data exposure

No evidence of data theft, and precautions taken anyway

The attacker had file-level access to the old server, which means they could have read the database. That database holds contact form entries, store customer records and the provider portal user list. There is no evidence they did. Everything they left behind was search-spam tooling, and this group's pattern is ranking hijacks, not data theft. "No evidence" is a reason for caution, not comfort, so these steps were taken regardless.

Already done
  • All admin passwords force-reset, with two-step login required for every admin.
  • Site moved off the old server onto Liquid Web's managed WordPress platform, with a new hosting account, new file-transfer access and a new database with new credentials.
  • Old server decommissioned.
  • Three old agency admin accounts removed. The eight remaining admins are all Collagen P.I.N. staff or our team.
Recommended for leadership
  • Precautionary portal password reset. Portal passwords are stored scrambled (hashed), so readable passwords were never exposed, but a reset costs little and closes the question.
  • Any further notification is a leadership decision under your own policies.
Response

Every action item is complete

  1. Check what Google sees on the three pages

    Done

    Google's live test returns the real page. Google's stored copy was still from Nov 2, so reindexing was requested.

  2. Review Google's security and penalty reports

    Done

    Search Console shows no security issues and no manual actions. The attacker's owner account is gone, and only our three agency owners remain.

  3. Full malware scan and file review

    Done

    Every WordPress core file was compared against a clean copy, and a high-sensitivity Wordfence scan of 46,088 files and 72,115 URLs found nothing. Database searches for the spam terms are empty, as expected, since the spam lived in static files.

  4. Close the entry point and change every password

    Done

    The theme is on the patched release, all credentials are new, and caches were flushed.

  5. Explain the "redi-version" tag

    Done

    It comes from the Redirect Redirection plugin, version 1.4.0. It is legitimate and unrelated to the hack.

  6. Ask Google to reindex the pages

    Requested

    Requests are in for the affected pages. The full set clears in about two days.

Unrelated to the hack

Two tracking issues, both diagnosed

  1. Lead tracking stopped around Sep 21

    Fixed

    The contact form itself never stopped working. It received about two submissions a day the whole time, including 40 from Oct 19 to Nov 5, all saved in Gravity Forms, so no leads were lost. Only the analytics event broke: a September Popup Maker update changed how it reported form submissions. The event now fires straight from Gravity Forms, and a test submission today appeared in Google Analytics as submit_lead_form within seconds.

  2. A "conversion" that counts page views

    Needs your OK

    ads_conversion_Submit_lead_form_1 is a Google Ads conversion set up on the Ads side to fire whenever someone loads the contact page. Because the form has three steps and each step reloads the page, one real submission today counted as seven conversions. Recommended: make submit_lead_form the key event, retire this one, and point the Ads conversion at the real event. This needs Editor access in Google Analytics, so either your team can mark it under Admin, Events, Key events, or grant our account Editor access and we will handle it.

A few test entries from "Test" with an seoaesthetic.com address came through today. Those were ours and have been deleted.

Going forward

What now protects the site

The site now runs on hardened hosting, and several layers watch for this exact kind of attack, so a problem reaches a person the same day.

Hardened hosting

Liquid Web's managed WordPress platform, with a new account, new file-transfer access and a new database.

Two-step logins

Required on every admin account, on top of fresh credentials everywhere.

File change alerts

Wordfence alerts, including file changes and scan results, go to a monitored team inbox.

Google alerts

Search Console ownership and security alerts go to the same inbox, so a new-owner notice reaches a person the same day.

Weekly updates

Plugin and theme updates on a weekly, logged schedule, with critical security fixes applied right away.

Uptime monitoring

The site is watched around the clock so an outage is flagged immediately.
